## Later the same day: three real bugs

Run the right way (`tools/debug/run_checks.py`, always 30 fps), one check still failed: the pilot chain. A review of the
runner also found four checks it called PASS that hid something. Each was diagnosed, then a second agent tried to
refute it. Three real bugs came out, all now fixed in `scripts/dungeon/dungeon.gd`.

1. **Autopilot looped on a Warp Eddy forever.** Tab autopilot planned its way with a map that knows walls but not
   traps. A warp it had already sprung, on the straight line into the stairs room, sent it to another room; it walked
   the same line back and stepped on it again. About 1 Warren replay in 15. It has been there since 2026-10-09; the
   10-14 pilot run was lucky. Fix: the autopilot walks round traps it has seen (`_field_round_traps`, used only when
   `_step_toward` is asked with `round_traps`). Same floors: 3 of 3 stuck before, 3 of 3 home after; 20 of 20 new floors home.
2. **Autopilot froze behind a Job Board client.** A client never steps aside, and one standing in the straight line to
   the goal left no shorter step, so the leader passed turns forever (8 of 40 test floors with jobs taken). Fix: the
   autopilot's own map treats clients as walls (40 of 40 reached the stairs). The autopilot also no longer heads for an
   item the bag cannot take (no run reaches that today: 10 kinds exist and the bag holds 10).
3. **The pause menu's Bag spent a turn during a boss scene.** Since 2026-10-10 the boss is awake while it talks, which is
   safe only because no turn runs during a scene. The keyboard and autopilot respected that; the Bag did not, so using
   an item mid-scene let the boss walk, gather a move, and on the crew scene start the meeting early. Fix: using an
   item is refused while a scene or a talk box is up, the same rule the keyboard follows.

Also found and fixed in the checks: `dungeon_recruit_check` stopped before the boss floor added on 2026-10-09 and never
cleared a run (it now beats the boss and asserts the recruit stays); `dungeon_chain_check` drove the leader with its own
rules from before levels existed (updated); `dungeon_teamsense_check` and `springvault_check` now test a real Archroot
instead of a Troughspine given Seep by hand; `hub_town_check` and `dungeon_action_check` skip screenshots headless
instead of hanging. `dungeon_pace_check`'s partner count is the normal leader and partner swap, not a regression.

Not a bug, noted: `dungeon_action_check` shows 1 sleep picture headless because the sleep loop runs on the real clock
while the check runs at a fixed 30 fps. In a window it should loop; not checked in a window yet.
